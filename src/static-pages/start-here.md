# Start Here

Build Log is a record of things I’m building, connecting, and troubleshooting: Windows, developer tools, AI assistants, memory, and automation. If you’re new here, these are a few ways into the writing.

## How it started

[How it started: nine bots in a week, then back to one](https://mikepred.github.io/build-log/how-it-started/)

I started with one AI assistant, ended up with a team of nine, then reconsidered how much of that organization was helping. This is the background to the log and the rules I wanted to keep from that experiment.

## Windows troubleshooting

[Windows Update pushed an AMD chipset driver over mine and broke boot](https://mikepred.github.io/build-log/windows-update-amd-chipset-driver-broke-boot/)

A driver update, a boot loop, and the repair log that helped explain what happened. The post follows the evidence, the recovery, and the changes I made to preserve more evidence if it happens again.

[My OneDrive’s problem was 322,219 files, not 268 GB](https://mikepred.github.io/build-log/onedrive-audit-file-count-not-size/)

A file-sync problem turned into an audit-tool project that was getting bigger before it had produced an inventory. Narrowing the task finally showed where most of the files were coming from.

## Giving automation useful boundaries

[Giving my Grok Bot assistant admin rights without switching off UAC](https://mikepred.github.io/build-log/ai-assistant-admin-without-breaking-uac/)

I wanted an assistant to carry out specific maintenance tasks on my PC. This covers the limited set of elevated tasks I gave it and how I checked what its account could actually do.

[One markdown file, three sites: what broke the first time my crosspost ran](https://mikepred.github.io/build-log/one-markdown-file-three-sites/)

The publishing pipeline behind this log sends posts to GitHub Pages, Hashnode, and dev.to. Its first real run exposed several problems, including a job that looked successful while part of the publishing had failed.
